    Registro de ciudadano

    Los nuevos registros entran con el rol ciudadano. Solo un administrador puede cambiarlo.

    Rostro

    Se guarda una huella matemática (128 números), cifrada con AES-256-GCM. No se guarda ninguna foto. Requiere cámara e internet (face-api.js se descarga la primera vez).

    Roles Composite

    Cada rol es un árbol: grupos completos de permisos y permisos sueltos, tratados igual.

      Usuarios registrados

      Los datos sensibles se ven enmascarados. Quitar permisos aplica de inmediato, incluso a sesiones abiertas; los permisos nuevos llegan cuando la persona vuelve a iniciar sesión. "Desbloquear" reinicia el límite de intentos (Decorator).

      Registrar entidad gubernamental

      La entidad recibe un client_id y un client_secret para consumir la API. El secreto se muestra una sola vez; el sistema solo guarda su hash.

      Entidades registradas

      Bitácora de auditoría

      Cada registro guarda el hash SHA-256 del anterior. Si alguien edita o borra una línea del archivo data/auditoria.jsonl, la cadena se rompe y se ve aquí.

      Integración con servicios gubernamentales

      Así se ve el sistema desde otra entidad del Estado (un hospital, una notaría, una alcaldía). No necesita implementar su propia autenticación: le pregunta al SGID si un documento corresponde a una persona registrada. La respuesta es mínima: sí o no, sin entregar datos personales.

      1. El administrador registra la entidad y le entrega client_id + client_secret.
      2. La entidad pide un token: POST /api/gov/v1/oauth/token (OAuth2 client credentials).
      3. Con el token consulta: POST /api/gov/v1/identidades/validar. El Proxy exige el permiso validar-identidad-externa y el Flyweight valida el formato del documento.
